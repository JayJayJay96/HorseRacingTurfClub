# UI Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved theme (`docs/superpowers/specs/2026-11-04-ui-theme-design.md`): one dark retro look with gold-trimmed see-through windows and pixel headings, ready for the Phase 8 HD-2D menus, plus the small layout fixes it lists for the big screen, the phone, Home and Stats. Same features and flows; no logic, data, sound or sim changes.

**Architecture:**
- **`src/app/theme.css`** (new, imported before `app.css`) holds the tokens, the `@font-face`, the page background, element base styles and the shared classes `.panel`, `.card`, `.chip`, `.glow`, `.topbar` (plus a one-line `.pixel` helper).
- **`src/app/app.css`** keeps screen layout only; its hard-coded colours become tokens.
- **Most screens restyle through element styles, with no JSX change.** JSX changes only where the spec asks for a layout fix: panels around groups, cards, the top bar, podium steps and the bet-slip radio cards.
- **Accessible names and roles stay the same.** The one exception is the phone's boxes line, whose text the private-race spec reads; that spec changes in the same task.

**Tech Stack:** React 19, TypeScript, Vite, plain CSS (custom properties, `:has()`, `color-mix()`), Playwright + @axe-core/playwright. No new dependencies.

## Ground rules (all tasks)

- **No logic changes.** Don't touch handlers, state, RPCs or data, and keep every `aria-*` attribute that exists today. Cards are real `<button>`s, or a `<label>` wrapped around a radio.
- **Contrast:** every text/background pair must be ≥ 4.5:1. The spec's tokens are chosen for this. The page gradient's turf end is mixed down to 30 % (Task 2) so plain text on the page keeps 4.5:1. Muted text on pure turf would be only 2.5:1.
- **Pixel font only at ≥ 16 px.** Anything smaller uses `system-ui`.
- **Prettier:** run `npx prettier --write <files>` on the files the task touched, never on the whole tree. Running it repo-wide rewrites about 90 files' line endings.
- **Pre-prettier indentation:** some JSX edits wrap existing lines in a new element and leave their indentation alone. That is expected; the prettier step re-indents them.
- **E2E needs the local stack:** `npx supabase start` (Docker) must be running. Playwright starts its own Vite on port 5180.
- **This is CSS and markup work, so there is no unit test to write first.** Each task's check is:
  1. `npm run typecheck`
  2. `npm run lint`
  3. the named e2e spec(s)
  4. the named screenshot check
- **Screenshot check procedure:**
  1. Start the Browser pane with `preview_start` `dev` (`.claude/launch.json`, port 5173, `--host`).
  2. Big screen: `http://localhost:5173`. Host a private race from `/`, add two names with "Add a name (no phone)", and tick them.
  3. Phone: open `http://127.0.0.1:5173/play?code=XXXX` in a second tab. A different origin means separate storage, so this tab is a different anonymous user. Join, then tick that name on the big screen.
  4. Set sizes with `resize_window`: 1920×1080 (TV), 1280×800 (laptop) and the `mobile` preset (375×812). Reset to `desktop` when done.
  5. Check that nothing overflows sideways, the trim and the focus ring show (Tab through), and the text is readable.
- **Commits:** at the end of each task, stage only that task's files. Never stage `.claude/`. Every message ends with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; two `-m` flags give the blank line.
